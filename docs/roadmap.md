# 功能路线图

路线图描述计划，不代表已交付功能或固定发布日期。当前阶段为 **R1-A：只读骨架与模拟验证**。

| 阶段 | 目标 | 通过条件 |
| --- | --- | --- |
| R1-A · 当前 | 只读适配器、状态核心、MCP 工具、桌面演示 | 模块与独立模拟检查、类型检查、构建通过 |
| 下一步 | 真实设备只读连接；桌面与 MCP 共享核心；外部只读投屏 | 在明确记录版本的真机上连接、断线恢复、两端状态一致，无非预期输入 |
| 基础交互 | 主屏点击、滑动、键盘输入、截图、暂停与接管 | 明确设备/显示目标，坐标映射正确，取消后不继续发送输入 |
| 文件工作区 | 授权目录浏览、搜索、传输、批量改名、文本编辑保存 | 路径限制、冲突处理、修改预览、写回结果验证与失败恢复 |
| 通知协同 | 通知查看；对支持系统回复的通知进行回复 | 明确目标、权限与内容；区分提交动作和确认结果 |
| 自动化任务 | 录制/编写重复操作，等待与条件判断，失败停止 | 可观察、可取消、可接管；重连与超时不会误操作 |
| 应用副屏实验 | 独立应用窗口与手机主屏并行使用 | 对具体机型/系统/应用验证显示与输入隔离，失败不回退主屏 |
| 扩展研究 | 剪贴板、OCR、照片归档、多设备、游戏操作 | 每项另设可重复的验收场景，不以演示替代稳定性测试 |

## 场景与限制

**在电脑回复微信。** 优先研究系统通知支持的回复动作；不支持时再评估可见界面操作。不能假定所有通知都可回复，也不依赖私有聊天数据库或未公开的微信接口。

**像文件夹一样管理手机文件。** 从用户可授权的共享目录开始，支持搜索、批量处理与编辑保存。安卓应用的私有数据目录不会自动变成电脑可读写目录。

**手机与电脑同时使用不同应用。** 应用副屏是重要研究方向，但存在应用多实例、焦点、音频、输入法和厂商限制。需要明确测试组合，不能承诺一切应用都完全互不影响。

**智能体玩《我的世界》手机版。** 需要持续感知、低延迟动作、任务规划和长期恢复。先验证短任务与可重复操作，再研究长任务；“自主通关”没有完成，也没有完成时间保证。

## 如何记录完成程度

- `SIMULATED_PASS`：固定数据与模拟适配器检查通过。
- `DEVICE_PASS`：有机型、安卓版本、应用版本、步骤和结果证据的真机通过。
- `NOT_RUN`：尚未执行，不能推断成功。

目前真实手机验收为 `NOT_RUN`。功能覆盖比例需先确定场景清单和通过标准，当前不宣称已经达到任何现有产品的 90% 功能。
